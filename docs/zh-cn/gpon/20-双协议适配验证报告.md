### 3.3 适配层重构

**main.c 的 17 处 `is_epon()` 已全部消除**：

```c
// 改造前
if (airoha_xpon_mode_is_epon(READ_ONCE(xpon->active_mode)))
        return airoha_xpon_epon_irq(xpon);
return airoha_xpon_xgpon_irq(xpon);

// 改造后
ops = airoha_xpon_proto(xpon);
if (!ops || !ops->irq)
        return IRQ_NONE;
return ops->irq(xpon);
```

新增 `airoha_xpon_proto_is_itu()` 替代 `!is_epon()` 的语义，可读性更好。

## 五、CI 触发方式

`openwrt-pon-drivers` 是 feeds 外部仓库，补丁通过
`scripts/apply-feed-patches.sh` 在 `feeds update -a` 之后自动应用。

CI 配置（`.github/workflows/build-firmware.yml`）：

```yaml
on:
  workflow_dispatch:
    inputs:
      config_seed:
        default: '2010.config'
      release_type:
        default: 'none'
```

**触发需要手动或 API 调用**（`workflow_dispatch` 不支持 push 自动触发）。

## 六、仍存在的限制（必须明确）

### 6.1 无法本地验证的部分

| 项 | 原因 |
|---|---|
| 完整固件编译 | 需 Linux 交叉编译链 |

**这些都是「知道怎么实现，只差接上游接口」，不是「不知道怎么做」。**

### 6.3 已知的潜在编译风险

CI 上可能遇到：

1. **内核 API 签名差异**——桩是按经验写的，真实内核可能不同
2. **`swab32` 等宏的可用性**——需 `linux/swab.h`
3. **`airoha_xpon_get_hir` 等上游函数**——需确认上游真的导出
4. **补丁与 feeds 版本的匹配**——若 naoki66 更新了 pon-drivers，补丁可能冲突

**这些只能在 CI 里发现，我无法本地预知。**
