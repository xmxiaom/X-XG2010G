## 一、新发现的缺口：AES 加密密钥（已修复）

### 怎么发现的

反汇编原厂 `gpon_enable @0x1a2c8`，提取完整调用序列：

```
gpon_enable (464 字节)
  01a334  gponDevResetCtrl        ← 我有
  01a338  gpon_dev_init           ← 我有
  01a390  gpon_qos_init           ← 我有
  01a40c  register_gpon_isr       ← 我有
  01a474  gponDevSetSerialNumber  ← 我有（但没在 enable 里调）
  01a488  gponDevSetEncryptKey    ← ❌ 我完全缺失
```

### 为什么是真实缺口

追踪调用链确认 `gponDevSetEncryptKey` 被 **`gpon_enable` 直接调用**，
即在启动路径上，不是可选功能。

缺失后果：OMCI 下发的加密密钥无法写入硬件，
**下行数据无法解密**。

### 上游有 crypto.c 但不覆盖 GPON

上游有 `airoha-xpon-crypto.c`（416 行），包含：
- `key_generate`（硬件密钥生成）
- `program_activation_keys`（激活密钥）
- `install_omci_msk`（OMCI 主密钥）
- `aes_encrypt_block` / `aes_cmac_32`（AES 加解密）
- `program_data_key` / `activate_data_key`（数据密钥交换）

但检查后发现：**全部使用 `xgpon_base` 和 `AIROHA_XGPON_*` 寄存器**，
是 XGPON 专用，不覆盖 GPON。所以 GPON 必须独立实现。

### 实现（完整还原）

原厂 `gponDevSetEncryptKey @0x023ce8`（484 字节）：

```
输入：16 字节 AES-128 密钥
1. 按大端拼成 4 个 u32：
   w0 = key[0]<<24 | key[1]<<16 | key[2]<<8 | key[3]
   w1 = key[4..7]
   w2 = key[8..11]
   w3 = key[12..15]
2. 写入 4 个 shadow 寄存器（顺序是反的）：
   0x4074 ← w3   (AES_KEY_SHADOW_REGISTER0)
   0x4078 ← w2   (REGISTER1)
   0x407c ← w1   (REGISTER2)
   0x4080 ← w0   (REGISTER3)
```

已实现 `airoha_xpon_gpon_set_encrypt_key()`，并接入 `gpon_enable` 第 6 步。

**安全设计**：全零密钥跳过写入——原厂用全零表示「未配置」，
写入全零会让硬件进入异常加密态。
