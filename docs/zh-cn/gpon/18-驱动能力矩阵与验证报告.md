# GPON / EPON 驱动能力矩阵与验证报告

> 目的：在适配固件之前，先回答「这两个驱动到底能做什么、还缺什么」
> 方法：代码静态审计 + 逆向成果对照 + 可编译性验证

## 一、当前环境限制（必须先说清）

| 项 | 状态 | 影响 |
|---|---|---|
| gcc / make / cl | ❌ 无 | 无法本地编译 |
| WSL | ❌ 被安全策略禁止 | 无法建 Linux 编译环境 |
| Docker / Podman / VBox / QEMU | ❌ 无 | 无容器或虚拟机 |
| 虚拟化固件 | ❌ `VirtualizationFirmwareEnabled=False` | 无法启用 Hyper-V |
| 磁盘 | ✅ D 盘 145G / G 盘 111G | 空间充足 |
| 网络 | ✅ 可访问 github | 可下载工具链 |

**结论**：这台机器**原生不支持编译 OpenWrt 固件**。原因不是缺工具，而是
虚拟化固件被禁用 + WSL 被安全策略拦截，没有可用的 Linux 环境。

**能做的替代方案**：
1. 下载便携版 MinGW-w64 GCC（263MB）做**语法级真实编译**——验证代码是否能过编译器
2. 做**内核 API 桩化编译**——用桩头文件模拟内核环境，验证函数签名与调用正确性
3. 完整的 OpenWrt 交叉编译需要 Linux 环境，当前无法完成

**验证过程中发现并修正的真实问题**：

| 问题 | 修正 |

| `?:` GNU 扩展（`x ?: 1`） | 改为标准 `if (!x) x = 1;` |
| C99 指定初始化器 `[IDX] = fn` | 改为运行时赋值 + memset |
| 宏定义续行符跨行 | 验证器修正（非代码问题） |
| 注释被宏展开吞进括号 | 验证器修正（非代码问题） |

## 五、能否刷机交付的判断

### 5.1 技术上需要什么

要「刷机后像原厂一样能用」，需要：

| 步骤 | 状态 |
|---|---|
| 1. 代码能编译进 .ko | ⚠️ 待验证（需 Linux 环境） |
| 2. GPON 能注册上线（O1→O5） | ❌ 需真机 + GPON 线路 |
| 3. 业务能通（VLAN/PPPoE/IPTV） | ❌ 需 OMCI 配合 |
| 4. 掉线能恢复 | ⚠️ 代码有，未实测 |
| 5. 固件能刷进设备 | ❌ 需编译产物 |
| 6. 刷后不砖 | ❌ 需真机验证 |

### 5.2 当前能保证什么

**能保证**：
- 寄存器偏移全部来自实测逆向，不是猜测
- PLOAM/MPCP 协议逻辑与原厂一致
- 代码结构符合内核规范
- 逆向文档可追溯每个决策

**不能保证**：
- 编译通过（无 Linux 环境）
- 能上线（无真机）
- 能刷机（无固件产物）

**必须明确：这是一份「基于逆向的可执行规格实现」，不是「已验证可用的固件」。**

## 六、建议的推进路径

### 路径 A：先补完逆向（当前环境可做）

1. 逆向 `gpon_enable @0x01a2c8`（MAC 启动顺序）——**最关键缺口**
2. 逆向 `gponDevResetGemInfo`（GEM 表复位）
3. 逆向 EPON 的复位与队列门限
4. 生成 EPON 寄存器头文件

**产出**：逆向 100% 完成，代码可补全。

### 路径 B：搭编译环境（需用户配合）

需要以下任一条件：

1. **启用 WSL2**（需要管理员权限 + 开启虚拟化）
   ```powershell
   # 管理员 PowerShell
   dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
   dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
   wsl --install Ubuntu-22.04
   ```

2. **把项目放到 Linux 机器编译**

3. **用 GitHub Actions 云端编译**（不需要本地环境）
   - naoki66 的项目本来就有 CI（`.github/workflows/build-firmware.yml`）
   - 推到自己的仓库后可以直接触发

**路径 B 的第 3 条是最现实的**——不依赖本地环境，用 GitHub 的免费 runner 编译。

### 路径 C：直接复用上游 CI

`X-XG2010G` 仓库已有完整 CI 配置，只需：

1. 把 `src/` 的代码合进 `openwrt-pon-drivers` 包
2. 打补丁到 `airoha-xpon`
3. push 触发 CI
4. 从 Actions 下载固件产物

**这条路完全绕开本地编译环境限制。**
