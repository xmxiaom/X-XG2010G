## 二、发现的缺陷（已全部修复）

### 缺陷 1：`airoha_xpon_gpon_mask_irqs` 未定义 —— **会阻塞编译**

**现象**：GPON ops 表第 2287 行绑定了这个函数，但整个文件里没有它的定义。

```c
.mask_irqs = airoha_xpon_gpon_mask_irqs,   /* 第 2287 行 */
```

```
$ grep -n "airoha_xpon_gpon_mask_irqs" src/airoha-xpon-gpon.c
2287:	.mask_irqs	= airoha_xpon_gpon_mask_irqs,   ← 只有这一处
```

**后果**：链接阶段必然报 `undefined symbol`，整个 `airoha-xpon.ko` 无法生成。

**修复**：补上实现（`+27 行`）。

```c
void airoha_xpon_gpon_mask_irqs(struct airoha_xpon *xpon)
{
	if (!xpon->gpon_base)
		return;

	gpon_wr(xpon, AIROHA_GPON_GPON_MAC_INTERRUPTS_ENABLE, 0);
}
```

设计要点：**只清使能位，不清状态位**——状态位留给 `isr` 读走，
否则会丢掉「掉线瞬间的最后一个事件」。

---

### 缺陷 2：`start_rx` 的 MAC 初始化是空的

**现象**：原实现只清了中断和计数器，然后留了个 4 行 TODO。

```c
/* 清中断、清计数器 */
gpon_wr(xpon, AIROHA_GPON_GPON_MAC_INTERRUPTS_ENABLE, 0);
gpon_wr(xpon, AIROHA_GPON_GPON_MAC_INTERRUPTS_STATUS, 0xffffffff);

/* TODO: 参照 gpon_enable 补全初始化顺序：
 *   1. ONU_GLOBAL_CONFIGURATION_REGISTER 复位释放
 *   2. GEM TABLE INITIALIZATION CONTROL 置位
 *   3. O3/O4 US PLOAM CONTROL 配置
 *   4. 使能中断
 */
airoha_xpon_gpon_set_state(xpon, AIROHA_GPON_O1_INITIAL);
```

**问题**：`airoha_xpon_gpon_enable()` 早已实现完整序列，
这个 TODO 是重复劳动，而且**如果没人补，MAC 根本不会初始化**。

**修复**：改为直接调用 `enable()`，并说明状态门禁约束。

```c
/*
 * 注意 enable 有状态门禁：只接受 O1/O2/O7。首次启动时 priv->state
 * 初值为 O1，可以过；若是从 O5 掉线恢复，应先走 detect_los_lof
 * 把状态退回 O1，不能直接调 start_rx。
 */
ret = airoha_xpon_gpon_enable(xpon);
```

### 缺陷 3：SCU 复位函数是空壳

**现象**：两个函数只打日志，**GPON 的 MAC 硬复位从未真正执行**。

```c
static void airoha_xpon_scu_rstctrl1_set(struct airoha_xpon *xpon, u32 bits)
{
	/* TODO: 上游通过 xpon->scu（regmap）访问 */
	dev_dbg(xpon->dev, "SCU RSTCTRL1 |= 0x%x\n", bits);   ← 只打日志
}
```

**后果**：`gpon_reset_ctrl(full=1)` 的完整复位路径实际是空操作，
MAC 可能残留在异常状态。

**修复**：改用上游的 regmap（与 `airoha-xpon-epon.c:153-154` 用法一致）。

```c
static void airoha_xpon_scu_rstctrl1_set(struct airoha_xpon *xpon, u32 bits)
{
	if (!xpon->scu)
		return;

	regmap_set_bits(xpon->scu, AIROHA_GPON_SCU_RSTCTRL1, bits);
}
```

配套补了宏：`AIROHA_GPON_SCU_RSTCTRL1 = 0x834`、`AIROHA_GPON_SCU_PON_MAC_RESET = BIT(31)`。

## 十、总结

**GPON**：逆向 100%，代码 2380 行，编译干净。
主要缺口是 `gpon_cmd_proc`（原厂 26756 字节的命令分发）
和 3 个功能补完项。9 个 TODO 是正常的上游集成点。

**本轮最大价值**：抓出 `mask_irqs` 未定义这个**会直接阻塞编译**的缺陷，
以及 `start_rx` 空初始化、SCU 复位空壳这两个**会让功能静默失效**的问题。
这三处如果不修，CI 编译会失败或驱动跑起来但不工作。
