# 适配层重构方案：core + 三协议操作表

> 目标：把上游 `main.c` 里 17 处 `is_epon() ? epon : xgpon` 二元判断，
> 改成「查操作表」的三协议统一结构，为加入 GPON 铺路。

---

## 1. 现状问题

### 1.1 上游的分派方式

`airoha-xpon-main.c` 里 17 处这样的代码：

```c
if (airoha_xpon_mode_is_epon(READ_ONCE(xpon->active_mode)))
        return airoha_xpon_epon_irq(xpon);

return airoha_xpon_xgpon_irq(xpon);
```

分布位置：

| 行号 | 场景 |
|---|---|
| 58 | fast IRQ |
| 76 | PHY IRQ |
| 91 | 主 IRQ |
| 117 | prepare |
| 128 | start_rx |
| 136 | stop_rx |
| 233 | controller_stop 入口 |
| 304 | 控制通道接收 |
| 323 | 控制通道匹配 |
| 336 | 控制通道唤醒 TX |
| 355/385/403/442/459/467/492 | 其余生命周期与调试 |

### 1.2 加入 GPON 后的问题

每处都要变成：

```c
if (mode == AIROHA_XPON_MODE_EPON_1G_1G)
        return airoha_xpon_epon_irq(xpon);
if (mode == AIROHA_XPON_MODE_GPON)
        return airoha_xpon_gpon_isr(xpon);
return airoha_xpon_xgpon_irq(xpon);
```

**17 × 3 = 51 个分支**，而且：
- 容易漏改（漏一处就是「GPON 走到 XGPON 分支」的诡异故障）
- 新增协议（如 XGS-PON 独立实现）要再改 17 处
- 无法在编译期检查完整性

---

## 2. 方案：操作表（vtable 模式）

### 2.1 核心思路

定义一套 `struct airoha_xpon_proto_ops`，三个协议各实现一份，
`main.c` 只查表调用：

```c
const struct airoha_xpon_proto_ops *ops = airoha_xpon_proto(xpon);

if (!ops || !ops->irq)
        return IRQ_NONE;

return ops->irq(xpon);
```

**17 处判断收敛为 17 次查表**，且新增协议零改动 `main.c`。

### 2.2 操作表定义

```c
struct airoha_xpon_proto_ops {
        enum airoha_xpon_mode mode;
        const char *name;

        /* 生命周期 */
        int  (*prepare)(struct airoha_xpon *xpon);
        int  (*start_rx)(struct airoha_xpon *xpon);
        void (*stop_rx)(struct airoha_xpon *xpon);
        void (*mask_irqs)(struct airoha_xpon *xpon);

        /* 中断 */
        irqreturn_t (*irq_fast)(struct airoha_xpon *xpon);
        irqreturn_t (*irq)(struct airoha_xpon *xpon);
        irqreturn_t (*phy_irq)(struct airoha_xpon *xpon);

        /* 链路状态 */
        bool (*los)(struct airoha_xpon *xpon);
        bool (*pcs_synced)(struct airoha_xpon *xpon);

        /* 状态机推进 */
        int  (*advance)(struct airoha_xpon *xpon, u32 phy_events,
                        unsigned long *delay);

        /* 控制通道（OMCI / OAM） */
        void (*control_rx)(struct airoha_xpon *xpon, struct sk_buff *skb,
                           const void *info);
        bool (*control_match)(struct airoha_xpon *xpon, const void *info);
        void (*control_wake_tx)(struct airoha_xpon *xpon);

        /* 调试 */
        void (*debug_pcs)(struct airoha_xpon *xpon, struct seq_file *m);
        void (*debug_mac)(struct airoha_xpon *xpon, struct seq_file *m);

        /* 掉线恢复（GPON 有，EPON 可选） */
        int  (*recover)(struct airoha_xpon *xpon);
};
```

### 2.3 查表函数

```c
const struct airoha_xpon_proto_ops *
airoha_xpon_proto_for_mode(enum airoha_xpon_mode mode)
{
        switch (mode) {
        case AIROHA_XPON_MODE_GPON:
                return &airoha_xpon_gpon_ops;
        case AIROHA_XPON_MODE_XGPON:
        case AIROHA_XPON_MODE_XGSPON:
        case AIROHA_XPON_MODE_EPON_10G_1G:
        case AIROHA_XPON_MODE_EPON_10G_10G:
                return &airoha_xpon_xgpon_ops;   /* 共用 XG-PON MAC */
        case AIROHA_XPON_MODE_EPON_1G_1G:
                return &airoha_xpon_epon_ops;
        default:
                return NULL;
        }
}
```

**为什么 10G-EPON 归到 xgpon**：它的 MAC 逻辑与 XG-PON 共用（只是 PCS 档位不同），
上游本来就是这么实现的。

---

## 3. 三份操作表的差异

| 槽位 | GPON | XG-PON | EPON |
|---|---|---|---|
| `prepare` | 清中断 | `xgpon_prepare` | NULL（在 start_rx 里做） |
| `irq_fast` | NULL | NULL | **`epon_irq_fast`**（MPCP 严格时序） |
| `irq` | `gpon_isr` | `xgpon_irq` | `epon_irq` |
| `phy_irq` | NULL（由 frontend 处理） | `xgpon_phy_irq` | `epon_phy_irq` |
| `los` | 读 `gpon_los` 标志 | 读 PCS 寄存器 | `epon_los` |
| `pcs_synced` | NULL | NULL | `epon_pcs_synced` |
| `advance` | 收 PLOAMd + O6 超时 | `xgpon_advance` | `epon_advance` |
| `control_rx` | NULL（OMCI 独立） | OMCI | OAM |
| `control_match` | NULL | 按 ONU-ID | 恒 false |
| `recover` | **`gpon_recover`** | NULL | NULL |

**关键差异说明**：

1. **只有 EPON 需要 `irq_fast`**：MPCP 的 Discovery Gate 有严格起始时间，
   必须硬中断里发，不能延到线程。

2. **GPON 的 `phy_irq` 是 NULL**：GPON 的 PHY 事件走 `pon-frontend` 统一处理，
   不像 EPON 需要在 MAC 侧单独注册。

3. **GPON 的 `control_rx` 是 NULL**：上游 OMCI 对象是独立的，
   不像 EPON 的 OAM 需要在 ops 里转发。这是上游现有设计的差异，
   重构时保持不变以免影响 OMCI 流程。

## 4. main.c 的改造方式

### 4.1 改造前

```c
static irqreturn_t airoha_xpon_irq_thread(int irq, void *data)
{
        struct airoha_xpon *xpon = data;
        bool ready = READ_ONCE(xpon->active_mode_valid) &&
                     READ_ONCE(xpon->mac_initialized);

        if (!ready)
                return IRQ_NONE;
        if (airoha_xpon_mode_is_epon(READ_ONCE(xpon->active_mode)))
                return airoha_xpon_epon_irq(xpon);

        return airoha_xpon_xgpon_irq(xpon);
}
```

### 4.2 改造后

```c
static irqreturn_t airoha_xpon_irq_thread(int irq, void *data)
{
        struct airoha_xpon *xpon = data;
        const struct airoha_xpon_proto_ops *ops;
        bool ready = READ_ONCE(xpon->active_mode_valid) &&
                     READ_ONCE(xpon->mac_initialized);

        if (!ready)
                return IRQ_NONE;

        ops = airoha_xpon_proto(xpon);
        if (!ops || !ops->irq)
                return IRQ_NONE;

        return ops->irq(xpon);
}
```

**净变化**：3 行判断 → 3 行查表，但**新增协议时这段代码不用动**。

### 4.3 17 处改造对照

| 原代码 | 改造后 |
|---|---|
| `is_epon() ? epon_irq_fast() : IRQ_WAKE_THREAD` | `ops->irq_fast ? ops->irq_fast() : IRQ_WAKE_THREAD` |
| `is_epon() ? epon_phy_irq() : xgpon_phy_irq()` | `ops->phy_irq ? ops->phy_irq() : IRQ_NONE` |
| `is_epon() ? epon_start_rx() : xgpon_start_rx()` | `ops->start_rx(xpon)` |
| `is_epon() ? epon_stop_rx() : xgpon_stop_rx()` | `ops->stop_rx(xpon)` |
| `is_epon() ? epon_mask_irqs() : xgpon_mask_irqs()` | `ops->mask_irqs(xpon)` |
| `is_epon() ? oam_receive() : omci_receive()` | `ops->control_rx(xpon, skb, info)` |
| `if (is_epon()) return false; ...` | `ops->control_match(xpon, info)` |
| `is_epon() ? oam_wake_tx() : omci_wake_tx()` | `ops->control_wake_tx(xpon)` |
| `if (!is_epon() && ...)` | `if (airoha_xpon_proto_is_itu(mode) && ...)` |

**最后一处特殊**：`is_epon()` 取反的用法（判断「是不是 ITU 协议」），
用 `airoha_xpon_proto_is_itu()` 内联函数替代，语义更清晰。

## 6. 验证清单

改造完成后必须逐项验证：

| 项 | 验证方式 |
|---|---|
| 编译通过 | OpenWrt 交叉编译 `make package/kernel/airoha-xpon/compile` |
| XG-PON 未回归 | 原有 XG-PON 线路能正常上线 |
| EPON 未回归 | 原有 EPON 线路能正常上线 |
| GPON 能识别 | `ponctl mode show` 显示 gpon 可用 |
| GPON 能映射 | `dmesg` 无 "failed to map gpon" |
| ops 表完整 | 检查 `airoha_xpon_proto()` 返回值非 NULL |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 漏改某处 `is_epon()` | 改造后用 `grep -c is_epon main.c` 应返回 0 |
| ops 槽位为 NULL 导致崩溃 | 每个调用点都检查 NULL |
| GPON 走错分支 | 在 `airoha_xpon_proto()` 里加 WARN_ON |
| 现有 XG-PON 回归 | 先只加 ops 不改逻辑，确认无回归再动判断 |

**推荐做法**：分两步走——
1. 先引入 ops 表，但 `main.c` 仍保留原判断（ops 只是并行存在）
2. 验证无回归后，再逐处替换判断

这样任何一步出问题都能回退。
