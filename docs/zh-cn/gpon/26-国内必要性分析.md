## 一、国内三大运营商的认证方式（已查证）

### 认证差异

| 运营商 | 认证方式 | 关键参数 |
|---|---|---|
| **中国联通** | LOID | 逻辑 ID（如 HSQ1234567）|
| **中国电信** | LOID + LOID Password | 双因子 |
| **中国移动** | PLOAM Password | 密码认证 |

### 对实现的硬性要求

| 需求 | 我的实现 | 状态 |
|---|---|---|
| GPON SN 写入（12 位，16 位需转字母码）| `program_identity` / `vssn[8]` | ✅ |
| PLOAMu 发送（携带 SN/密码）| `send_ploamu` | ✅ |
| PLOAMd 接收与分派（OLT 下发配置）| `recv_ploamd` / `dispatch_ploamd` | ✅ |
| O3/O4 阶段 PLOAM 交互 | 寄存器 `0x43c4` 用硬件默认值 | ✅ 默认值可用 |
| 注册状态机 O1–O7 | `set_state` / `write_state` / `advance` | ✅ |
| AES 加密（电信部分区域要求）| `set_encrypt_key` | ✅ 本轮新补 |

### 关键发现：`0x43c4` 不需要显式配置

原厂有两个函数操作 `0x43c4`（O3/O4 US PLOAM CONTROL）：
- `gponDevSetO3O4PloamCtrl`（120 字节）
- `gponDevSetSendPloamuWaitMode`（160 字节）

但追踪调用链发现：**两者都没有任何直接调用者**，是导出给上层或 hook 用的 API。
GPON 也没有 EPON 那样的寄存器初始化表（只有 GEM MIB 表），
说明 `0x43c4` 靠硬件默认值即可正常工作。

**结论：不配置这两个寄存器也能完成国内注册。**

## 三、剩余功能逐项判定

### 3.1 密钥轮换类（3 个，可不实现）

| 函数 | 字节 | 调用者 | 判定依据 |
|---|---:|---|---|
| `gponDevSetShadowKey` | 200 | **无** | 密钥轮换 API |
| `gponDevSetAesKeySwitchBySw` | 236 | `SetKeySwithTime` / `dvt` | 软件触发切换 |
| `gponDevSetKeySwithTime` | 212 | **无** | 切换时间配置 |

**为什么不需要**：三者都无实际调用者（只有 DVT 测试用）。
首次注册只需 `gponDevSetEncryptKey`（已实现）。
密钥轮换是长期运行的增强功能，国内运营商通常不主动触发。

### 3.2 DBA 微调类（6 个，可不实现）

| 函数 | 字节 | 寄存器 | 判定 |
|---|---:|---|---|
| `gponDevSetDbaSlightModify` | 148 | `0x4340` | 无调用者 |
| `gponDevSetDbaShiftModify` | 148 | `0x4340` | 无调用者 |
| + 4 个 Green/Total/Yellow 变体 | 各 100–148 | `0x4340` | 无调用者 |

**为什么不需要**：全部操作同一个寄存器 `0x4340`（DBA backdoor），
是运营商侧调优参数。家庭宽带用默认值即可。

### 3.3 统计类（3 个，可不实现）

| 函数 | 字节 | 判定 |
|---|---:|---|
| `gponDevGemMibTablesInit` | 272 | 仅计数器用 |
| `gponDevGetGemMibIdxTable` | 368 | 仅统计 |
| `gponDevClearGemPortCounter` | 184 | 仅统计 |

**为什么不需要**：GEM 计数器用于网管监控，不影响数据转发。

### 3.4 纯日志类（1 个，可不实现）

`gpon_dev_get_error_status`（744 字节）虽然被 `gpon_isr` 调用，
但反汇编显示它的全部逻辑是：

```
gponDevGetErrStatus(&status);
printk(...) 对每一位 ubfx + 打印，共约 20 次
```

**没有任何功能动作，纯日志输出。** 不影响链路。

### 3.5 告警记录（2 个，可不实现）

| 函数 | 字节 | 调用者 |
|---|---:|---|
| `gpon_record_emergence_info` | 420 | 只被 `typeb_dev_reset` / `handle_xpon_daemon_job_gpon_dev_reset` |
| `gpon_show_emergence_info` | 504 | 只被 DVT 调用 |

**为什么不需要**：只服务 TypeB 保护倒换和守护进程，家庭宽带不涉及。

### 3.6 TypeB 保护倒换（3 个，不需要）

| 函数 | 字节 |
|---|---:|
| `gpon_typeb_dev_reset_for_typeB` | 1176 |
| `gpon_dev_typeB_restore` | 760 |
| `gpon_typeb_dev_reset` | 332 |

**为什么不需要**（已查证）：

TypeB 是**运营商级保护**：
- Type B 单归：同一 OLT 两个 PON 口主备
- Type B 双归：两台 OLT 互备
- Type C：每一级都双份（政府/金融/医院专用）

**家庭宽带（FTTH）不部署 TypeB**——它是局端设备级冗余，
ONU 侧不需要参与倒换逻辑。

### 3.7 调试/DVT/测试（21 个，不需要）

包括 `gponDevDumpCsr`（4452B）、`gponDevSetSniffMode`（1820B）、
`gpon_dbg_grp_err_check`（1452B）、`gpon_dvt_*` 系列等。

**生产固件不需要。**

### 3.8 厂商定制（39 个，不需要）

包括 `gponDevSetNewTod`（1440B，时间同步）、
`gponDevClearHwCounter`（352B）、`gpon_show_emergence_info`（504B）等。

**运营商定制功能，非标准 GPON 协议。**

### 3.9 ioctl 统计查询（2 个，不影响上网）

`gpon_cmd_proc`（26756B）+ `gponDevGetSuperframe`（超帧，已实现）。

已实现超帧读取；`gpon_cmd_proc` 的完整 ioctl 表只服务网管查询，
**不影响上网、IPTV、语音等业务**。

## 四、EPON 在国内的适用性

### 国内部署现状（已查证）

| 运营商 | 主要 PON 制式 |

**关键**：中国电信大量使用 EPON，所以 EPON 支持对国内是**必需的**。

## 六、回答「国内功能是否完整」

### 可以确定地说

**国内 GPON/EPON 上网、IPTV、语音所需的协议功能，全部已实现。**

依据：
1. 三大运营商认证方式（LOID / LOID+PW / PLOAM Password）所需的
   SN 写入、PLOAM 收发、状态机、加密——全部实现
2. 数据通路（GEM / Alloc-ID / T-CONT / DBA）——全部实现
3. 链路保持（中断 / LOS / TO1-TO2 / 恢复）——全部实现
4. EPON 完整（电信大量使用）——上游协议逻辑 + 349 条寄存器表

### 但不能确定地说

1. **349 条 EPON 表未经真机验证** —— 无公开参照，只有内部一致性证据
2. **真实内核编译未通过** —— 第 6/7 次 CI 仍在跑
3. **零真机验证** —— 没有在真实 OLT 上注册过

### 需要注意的国内特有事项

| 事项 | 说明 | 我的支持 |
|---|---|---|
| GPON SN 格式 | 必须 12 位；16 位需把前 8 位转字母码 | 需在用户态处理 |
| LOID 格式 | 2-3 位大写字母 + 7 位数字（如 HSQ1234567）| 需在用户态处理 |
| 光功率 | -8 ~ -27 dBm 可用，>-20 良好 | 需 `debug_mac` 读取 |
| VLAN | 上网/IPTV/语音/管理（TR069）分离 | 需用户态配置 |
| IPv6 前缀 | 国内一般 /60 前缀委派 | 上游 netdev 处理 |

**这些都需要在用户态（LuCI / UCI 配置）配合，不是驱动层能单独完成的。**
